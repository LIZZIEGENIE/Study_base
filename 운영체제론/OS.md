# 운영체제론


## Chap 1. 운영체제(Operating System)
- 운영체제 - 컴퓨터 자원을 할당 및 관리하는 **시스템 소프트웨어**
### 분류 - ***응답시간*** 과 ***데이터 입력 방식*** 에 따른 분류
- 일괄처리 시스템 (batch processing system)
- 다중 프로그래밍 시스템 (multi-programming system)
- 시분할 시스템 (time-sharing system)
- 다중 처리 시스템 (multi-processing system)
    - 강결합 시스템, 한 컴퓨터 안에 여러 CPU·코어. 보통 메모리 등을 공유하므로 이미지에서는 강결합으로 연결
- 실시간 처리 시스템 (real-time processing system)
- 분산 처리 시스템 (distributed processing system)
    - 약결합 시스템, 독립된 여러 컴퓨터가 네트워크로 협력. 각자 메모리를 가지므로 약결합으로 연결

<br>

| 종류 | 핵심 개념 | 기억할 장면 |
|---|---|---|
| **일괄처리** | 작업을 **모아서 한꺼번에** 처리 | 한 달 치 급여 계산을 모아 실행 |
| **다중 프로그래밍** | 한 작업이 입출력을 기다리면 **다른 작업으로 CPU를 계속 사용** | A가 디스크를 기다리는 동안 B 실행 |
| **시분할** | CPU 시간을 **짧게 나눠 번갈아** 배정 | 여러 사용자가 각자 즉시 반응을 받는 것처럼 사용 |
| **다중 처리** | CPU·코어를 **여러 개 써서 실제로 동시에** 처리 | 코어 1은 A, 코어 2는 B 실행 |
| **실시간 처리** | 정해진 **시간 안에 반드시** 처리 | 자동차 제동 제어가 기한 안에 반응 |
| **분산 처리** | **여러 컴퓨터가 연결되어** 작업을 나눠 처리 | 여러 서버가 계산을 분담 |

<br>

- **다중 프로그래밍은 ‘대기 시간을 활용’, 시분할은 ‘시간을 쪼개 배정’, 다중 처리는 ‘CPU를 늘림’**

- 간단하게
    - 일괄 = 모아서 / 다중 프로그래밍 = 기다릴 때 다른 일 / 시분할 = 조금씩 번갈아 / 다중 처리 = 여러 CPU / 실시간 = 기한 안에 / 분산 = 여러 컴퓨터

<br>

| 구분 | 다중 프로그래밍 시스템 | 다중 처리 시스템 |
|---|---|---|
| 핵심 | 여러 프로그램을 준비해 두고, 실행할 수 있는 프로그램에 CPU를 배정 | 여러 CPU·코어가 작업을 나눠 실행 |
| 주된 목적 | 입출력 대기 중에도 CPU가 일하도록 활용률을 높임 | 실제 병렬 실행으로 처리 능력을 높임 |
| CPU 하나로 가능? | **가능** | **불가능** — 처리 장치가 여러 개 필요 |
| A와 B의 실행 | CPU 하나라면 같은 순간에는 하나만 실행 | 서로 다른 코어에서 같은 순간에 실행 가능 |

## Chap 2. 프로세스와 스레드
### 프로세스(process) - 프로그램에 대한 인스턴스
- 실행 중인 프로그램. 운영체제에서 **작업의 기본 단위**. 반드시 한 개의 PCB와 연결됨. **비동기적인 행위**를 일으키는 주체 *('비동기적인 행위'란 각 프로세스가 다른 프로세스와 항상 발맞춰 실행되지 않고, 각자의 진행 샅애에 따라 실행하고 대기를 한다는 의미)*.

### PCB(Process Control Block), 프로세스 제어 블록
- 프로세스에 대한 중요한 정보 제공하여 프로세스를 정의해주는 데이터 블록  (프로세스를 제어하고 관리하는 데 필요한 정보를 담은 자료구조. 운영체제가 PCB를 읽고 갱신할 수 있도록 정보를 담아놓음)
- 프로세스를 생성할 때 만들어지며 프로세스가 종료되면 같이 삭제됨

### 프로세스 생성 과정
1. 프로세스 식별자(PID) 할당
    - 새 프로세스를 위한 고유 식별자인 PID를 할당함
2. 주소 공간과 PCB 할당
    - 새 프로세스를 위한 주소 공간과 프로세스 제어블록(PCB)을 할당함
3. PCB 초기화
    - 새 프로세스의 PCB를 초기화 함
4. 준비 큐에 프로세스를 삽입
    - 새 프로세스를 스케줄링 큐의 준비 또는 준비/보류 리스트에 연결

### 프로세스의 메모리 구조
1. 스택(stack) - **데이터를 일시적으로 저장**
    - 지역변수, 호출한 함수의 반환 주소(복귀 주소), 반환 값, 매개변수 등에 사용함
2. 힙(heap) - **사용자가 동적으로 할당 및 해제**
    - 프로그램 실행 중 동적으로 메모리를 할당하기 위해 사용함
3. 데이터(data)
    - 전역변수(global)나 정적변수(static)를 할당하기 위해 사용함
4. 코드(code)
    - 컴파일한 프로그램의 코드나 명령어 등이 저장됨

### 프로세스 종류
1. 역할에 따른 분류
    - 시스템 프로세스(운영체제 프로세스, 커널 프로세스) : 사용자 작업 처리를 위해 시스템 관리 기능을 담당하는 프로세스
    - 사용자 프로세스  : 사용자 응용 프로그램을 수행하는 프로세스
2. 병행 여부에 따른 분류
    - 독립 프로세스 : 다른 프로세스에게 영향을 주지 않고 영향을 받지도 않으면서 수행하는 프로세스
    - 병행(협력) 프로세스 : 여러 개의 프로세스들이 동시에 수행되면서 다른 프로세스에 영향을 주거나 영향을 받으면서 수행되는 프로세스

### 프로세스 상태
- 23p 참고
- 생성 -> 준비 -> 실행 ->종료
            대기
1. 생성(new) : 필요한 자원(PCB/주소 공간 등)을 할당받은 상태
2. 준비(ready) : CPU 할당(스케줄링)을 기다리는 상태
3. 실행(running) : CPU 할당받아 수행되는 상태
4. 대기(waiting/blocked) : 수행에 필요한 요구사항(자원/입출력 요구/페이지 교환 등) 충족을 기다리는 상태
    - 프로세스가 원하는 자원이 할당되기를 기다리거나, 이벤트가 일어나기를 기다리는 상태
    - 프로세스의 실행 과정에서 여러 번 대기 상태에 속하게 될 수 있음
    - 대기 상태의 프로세스들은 CPU 할당을 위한 스케줄링에서 제외됨
5. 완료, 종료(terminated) : 작업이 완료되어 자원을 반환하는 단계
    - 프로세스가 작업 수행을 끝낸 상태, 프로세스에 할당된 모든 자원을 운영체제에게 돌려줌

### 프로세스 상태 전이
1. dispatch, 준비-> 실행 : CPU 할당받은 경우
    - 준비 상태의 프로세스가 디스패처(dispatcher)에 의해 CPU를 할당받으면 실행 상태로 전이됨
2. time-out, 실행 -> 준비 : 시간 할당량을 다 쓴 경우/선점당한 경우
    - 실행 상태 프로세스의 시간 할당량이 모두 소진되었을 때, 다른 준비 상태의 프로세스가 있다면 실행 중읻너 프로세스는 커널에 의해 스케줄링되기를 기다리는 준비(ready) 상태로 전이됨
    - 실행 상태에 있는 프로세스가 우선순위가 높은 프로세스에 의해 선점되었을 때 준비 상태로 전이 됨
3. block, 실행 -> 대기 : 요구사항(자원 필요/이벤트 발생)이 발생한 경우
    - 실행 상태의 프로세스가 입출력을 수행하기 위해 입출력 요청을 하면 스스로 CPU를 반납하고 입출력이 완료될 때까지 대기(blocked 또는 waiting)상태로 전이 됨
    - 프로세스가 실행 중에 파일 읽기 수행을 커널에 요청했지만 파일의 내용이 파일 캐시에 없는 경우, 프로세스는 대기 상태로 전이 됨
4. wake-up, 대기 -> 준비 : 요구 사항이 충족된 경우

### 문맥교환, context switching : CPU 할당 전환 시 이전 상태를 저장(백업)하고 새로 초기화
- CPU를 다른 프로세스로 전환할 때, 이전의 프로세스 상태 레지스터의 내용을 보관하고, 새로운 프로세스의 레지스터들을 적재하는 과정
- 운영체제에서는 문맥교환이 자주 일어나기 때문에 과부하(overhead)가 발생할 수 있으므로 문맥교환에는 가능한 효율적으로 구현된 스레드(thread)를 사용한다.

### 스레드(thread) : 경량 프로세스
- 프로세스의 실행의 개념만을 분리한 것으로, 경량 프로세스 라고도 함. **(제어를 분리한 실행 단위)**
- **CPU 스케줄링의 기본 단위**
- 하나의 프로세스에 1개의 스레드 -> 단일 스레드
- 하나의 프로세스와 2개 이상의 스레드 -> 다중 스레드
- 동일한 프로세스 내 스레드들은 각각 레지스터와 스택 영역을 독립적으로 가지고, 힙과 데이터, 코드 영역은 서로 공유함
- 멀티 프로세서 환경에서는 각각의 스레드가 다른 프로세서에서 수행 될 수 있기 때문에 다중 스레드를 이용하면 병렬처리가 가능함
- 같은 프로세스에 속한 스레드끼리 문맥 교환을 수행하면 스택영역만 교환하면 되므로 문맥 교환의 속도가 생대적으로 빠름
- 다른 프로세스에 속한 스레드 간의 자원 공유로 인해 교착상태와 같은 동기화 문제가 발생할 수도 있음

#### 프로세스와 스레드의 통신 방식
1. 프로세스 간 통신
    - IPC(Inter-Process Communication) 방식을 이용함
    - 커널이 개입되므로 오버헤드가 크다
2. 스레드 간  통신
    - 동일한 프로세스 내부에 포함되는 스레드끼리 공통적으로 접근 가능한 공유 메모리 영역을 통해 효율적으로 통신함
    - 커널이 갱비하지 않으므로 오버헤드가 작음

#### Pthread
- 스레드 생성과 동기화를 위해 POSIX가 제정한 표준 API

## Chap 3. 병행 프로세스

### 병행 프로세스(concurrent process)
- 프로세서 하나는 한번에 프로세스 하나만 실행 가능
- 단일 프로세서 시스템에서 운영체제가 프로세서 시간을 나누고 프로세서를 빠르게 전환하여 마치 프로세스 여러 개를 동시에 실행하는 것처럼 보이게 하는 것이다

### 상호 배제와 동기화 기법
1. 임계영역, 임계 구역(critical section) : 공유 영역
    - 프로세스나 스레드들이 공유 자원(전역변수)에 동시 접근할 때 그 접근 영역을 임계 구역이라 한다.
    - 주어진 시점에 오직 하나의 프로세스만 진입 가능
    - 어떤 프로세스가 공유 데이터를 읽는 중이면, 다른 프로세스는 해당 데이터를 읽을 수 있다
    - 어떤 프로세스가 공유 데이터에 쓰는 중이면, 다른 프로세스는 해당  데이터를 읽을 수 없다.
2. 세마포어(semaphore) : P(wait, count--), V(signal, count++) 연산 이용
    - 상호배제 문제(임계구역 문제)를 해결하기 위한 동기화 도구
    - 표준 단위 연산인 P-연산(wait)과 V-연산(signal)을 사용하여 접근할 수 있는 정수형 공유변수를 의미함
    - 세마포어를 구현할 때 발생할 수 있는 바쁜 대기(busy waiting) 때문에 CPU의 시간 낭비가 발생할 수 있다
    - P 연산과 V 연산의 구현 방법에 따라 바쁜 대기(busy waiting)를 해결할 수 있따
    - 세마포어 동작은 중단될 수 없는 원자성을 가짐 -> P, V 연산 

    #### 세마포어의 종류
    1. 이진(binary) 세마포어
    - 사용 가능한 상태는 1, 사용 불가능한 상태는 0으로 나타낸다.
    2. 계수형(counting) 세마포어
        - 0과 1 뿐만 아니라 2, 3, 4 등 0 이상의 양수값을 사용하는 방식

    #### 바쁜 대기(busy waiting)
    - 공유 자원이 이미 사용 중일 때, 스레드가 공유 자원이 사용 가능해졌는지 계속해서 검사하며 대기하는 것을 의미 -> **무한루프 + 조건문**
    -  CPU의 자원 낭비 발생

3. 모니터(monitor) : 모듈(공유 데이터 + 프로시저 + 초기화 코드)
    - 공유 데이터, 임계 영역이 코딩된 프로시저, 초기화 코드로 구성된 모듈임

### 임계영역 문제 및 해결 조건
1. 상호 배제(mutual exclusion) : 한 번에 한 프로세스만 임계구역 진입
    - 한 번에 한 프로세스만이 임계지역을 수행하도록
    - 둘 이상의 프로세스가 동시에 하나의 임계지역에 진입하지 않게
    - 임계 구역을 보호하기 위한 병행 프로세스 동기화 기법
2. 진행(progress) : 다른 프로세스의 임계구역 수행을 방해받지 않음
    - 프로세스는 자신이 임계지역을 수행하지 않으면서 다른 프로세스가 임계지역을 수행하는 것을 막으면 안됨
3. 제한된 대기(bounded waiting) : 일정 시간 내에 임계구역에 진입 가능
    - 프로세스의 임계지역 진입은 유한 시간 내에 이루어져야 함


## Chap 4. 교착 상태
### 교착상태(deadlock)
- 둘 이상의 프로세스들이 서로 다른 프로세스가 점유하고 있는 자원을 기다리느라 어느 프로세스도 진행하지 못하는 상태

### 교착상태 발생 조건
- 조건을 모두 만족해야 교착상태 발생
- 조건 중 하나라도 만족하지 않으면 교착상태 발생 x
1. 상호 배제(mutual exclusion) : 자원 동시에 사용 불가능
    - 여러 프로세스들이 같은 자원을 동시에 사용하지 못하게 하는 경우
    - 프로세스가 자원을 사용(점유) 주일 때는 다른 프로세스가 자원을 사용하지 못하고 대기
    - 프로세스들은 필요로 하는 자원에 대해 배타적인 통제권을 가짐
2. 점유와 대기(hold and wait) : 부분할당 상태에서 또 다른 프로세스의 자원을 또 요구하며 대기
    - 이미 하나 이상의 자원을 점유(할당)한 프로세스가 다른 프로세스에 의해 점유(할당)된 자원을 요청하며 대기하고 있다
3. 비선점(non-preemption) : 자원은 종료될 때까지 자기꺼임
     - 프로세스가 점유(소유)하고 있는 자원은 다른 프로세스에 의해 선점 될 수 없음. -> **강제로 빼앗기지 않음 / 양보되지 않음**
     - 한 프로세스에게 할당된 자원은 그 프로레스가 사용을 완전히 종료하기 전까지는 해제되지 않는 경우
4. 순환 대기, 환형 대기 (circular wait) : 순환적으로 서로의 자원을 요구
    - 각 프로세스는 순환적으로 다음 프로세스가 요구하는 자원을 가지고 있다
    - 프로세스 간에 닫힌 체인(closed chain)이 존재하여, 체인 내의 각 프로세스는 체인 내의 다른 프로세스에 의해 소유되어 있는 자원을 상호 요청하며 대기하고 있다
    - 각 프로세스들이 서로 다르 프로세스가 가지고 있는 자원을 요구하며 하나의 순환(cycle) 구조를 이루는 경우

### 교착상태 처리 기법 : 예방 / 회피 / 탐지 / 회복
1. 교착상태 예방 : 교착상태 발생조건 부정(미리 제거)
    - 교착상태의 발생 조건을 사전에 미리 제거하는 방법
    - 교착상태를 예방하기 위한 방법에는 점유와 대기 방지, 비선점(non-preemption) 방지, 순환대기 방지 방법이 있다.
    - 상호배제 조건의 부정은 교착상태를 예방
    - 프로세스들이 필요로 하는 자원에 대한 배타적인 통제권을 갖지 않게 하여도(상호배제 부정) 교착상태의 발생을 막을 수 없음
    
    #### 교착상태 예방 조치 : 상호배제 부정은 예방 불가능
        1. 점유와 대기 부정 : 모든 자원 할당 후 실행(완전할당)
            - 한 프로세스가 실행되는 데 필요한 모든 자원을 할당한 후 실행시킴
            - 모든 자원이 할당될 때까지 지연됨에 따라 성능저하가 발생할 수 있음
        2. 비선점 부정 : 자원 반납 후 자원 요구
            - 자원을 점유하고 있는 프로세스가 다른 자원을 요구할 때, 점유하고 있는 자원을 반납하고 요구하도록 함
        3. 순환대기 부정 : 선형 형태로 자원 요구
            - 자원에 선형으로 고유번호를 할당하고, 각 프로세스는 현재 점유한 자원의 고유번호보다 큰 번호 방향(한 방향)으로만 자원을 요구하도록 함


2. 교착상태 회피 : 자원할당 상태 확인(안정/불안정)
    - 운영체제가 자원할당 상태를 능동적으로 확인하여 안정 상태와 불안정 상태를 판단하여 교착상태를 회피하는 방법
    - 시스템이 상태가 불안정할 때는 교착상태가 발생할 수 있으므로 시스템이 항상 안정 상태에 있을 때만 자원 요청을 허용함
    - 안정 상태란 주어진 자원으로 모든 프로세스 수행이 가능한 경우를 의미함
    - 불안정 상태란 주어진 자원으로 모든 프로세스 수행이 불가능한 경우

        #### 은행원 알고리즘 : 교착상태 회피
            - 은행원 알고리즘은 대표적인 교착상태 회피 알고리즘으로 사용됨
            - 은행원 알고리즘은 이미 교착상태가 발생한 경우 적용할 수 없음
